Install it

Pick where you want it to live. Everything below follows both choices.

macOS, Linux, or WSL — paste this into Terminal:

curl -fsSL https://claude.ai/install.sh | bash

Windows PowerShell:

irm https://claude.ai/install.ps1 | iex

Your prompt tells you which Windows shell you're in — PowerShell shows PS C:\, CMD shows C:\ without the PS. On native Windows also install Git for Windows, so the agent can run shell commands through Git Bash.

Package managers work too: brew install --cask claude-code, winget install Anthropic.ClaudeCode, or npm install -g @anthropic-ai/claude-code (Node 22+). The curl installer auto-updates in the background; the package managers don't.

Now ask it something read-only. Real questions worth trying:

  • “Explain how the main entry point works in this repo. Which files own it?”
  • “What do our checks actually run before a PR can merge?”
  • “Which parts of this codebase are safe to change, and which are load-bearing?”

Watch what it does before it answers: it lists directories, opens files, greps for symbols. That's the whole thing. It went and looked.

claude --version   # prints e.g. 2.1.228 (Claude Code)
claude doctor      # read-only health check — fixes nothing, breaks nothing

If claude isn't found, install troubleshooting matches your exact error to a fix. Never install with sudo npm install -g.

codex --version   # prints e.g. codex-cli 0.147.0
codex doctor      # checks install, auth, config, and runtime health
Ask it to explain things for your first few sessions. Resist asking it to change anything until we've paired. The repo has real gates and a real branch protocol, and those are much easier to learn with someone beside you than to unpick afterwards.
Send at least one prompt before you close it. That first message is what registers the claude-cli:// link handler with your OS — installing alone doesn't do it. Until you've sent one, the launch buttons on the Dashboard will silently do nothing when you click them.

The three things that replace copy-pasting

If you take nothing else from this page, take these.

  1. It reads the files itself. Never paste a file, a stack trace, or a chunk of config. Name it — “look at src/server/session.ts” — and it opens it. Pasting actively makes the answer worse, because it only sees the fragment you chose instead of the code around it.
  2. The repo already briefs it. AGENTS.md loads automatically at the start of every session: the stack, the conventions, the gates, the ticket protocol. You never re-explain the project.
  3. Sessions come back. claude --continue picks up where you left off; claude --resume (or /resume inside a session) lets you choose an older one. In the desktop app and IDE extension, your conversations are listed in the sidebar. No re-establishing context by re-pasting.

See the handoff before you configure it

These three drawn snapshots are a visual brief for the person setting up a hub and the agent assisting them. They show the same template moving from unconfigured to human-enabled to actively shared.

The human flips the switch. An agent may prepare the config after a person chooses what to share, names the accountable owner, and explicitly asks for help. It cannot enable the log, choose its owner, or opt itself in.

Shared updates are opt-in

This hub can expose a central Activity page and let an agent add concise workstream updates. It only appears after a human enables it in site/hub.config.js, names the human owner, and asks for an update. An agent cannot opt itself in.

It is a pointer, not a transcript. Updates cover outcomes, milestones, decisions, blockers, or next steps and link to the real project record. Never put private reasoning, messages, credentials, personal or customer data, raw logs, or secrets there. Humans remain accountable for decisions and external actions.
